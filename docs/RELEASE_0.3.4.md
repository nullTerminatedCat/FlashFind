# 闪寻 FlashFind 0.3.4（预览版）

本版减少百万级结果的名称排序开销，并修复元数据漏更新、移入目录过滤和区分大小写通配符的问题。

## 性能优化

- **名称排序直接复用索引顺序**：新搜索和切换排序均使用名称升序的匹配缓存；升序直接交付，降序原地反转，避免重复建立排名、分配排序键和多线程归并。同名项的顺序保持一致。
- **实际值未变化时不生成索引快照**：大小和修改时间查询结果与索引相同时，不复制条目块、不合并名称索引，也不因此触发整库保存。
- **空 USN 批次提前返回**：没有变化时不建立全库 FRN 和父子关系辅助索引。
- **删除优先于补查**：同批已经删除的文件不再发送元数据查询；同一文件的重复变化只补查一次。

## 修复

- 只有 `BASIC_INFO_CHANGE` 的批次也能刷新文件修改时间，解决此前必须碰巧伴随创建、删除或数据写入才刷新的问题。
- 元数据补查失败时保留已知大小和修改时间；USN 事件时间不再替代已有文件的最后写入时间。部分查询成功时只更新成功的字段。
- 目录从索引范围外移入后，补扫的每一项均应用排除列表和“仅包含目录”。被过滤目录的子项也不会进入索引。
- 启用“区分大小写”后，含 `?` 或多个 `*` 的通配符正确区分名称大小写，例如 `R?port.txt` 和 `r?port.txt`。
- 汇入 0.3.3 之后已有的多选状态保持和 F5 软刷新修复：F5 刷新结果及选中项属性，Ctrl+F5 重建索引。

## 本机性能对比

Release x64，MSVC 14.51，226 万条合成索引。相同数据、相同结果顺序，在同一个程序中交替执行通用排序路径与优化路径；每个方向预热一轮，再取五轮中位数。计时包含结果数组复制和排序处理。

| 操作 | 原路径 | 优化后 | 提速 |
|---|---:|---:|---:|
| 名称升序：复制结果＋排序 | 20.79 ms | 1.32 ms | 15.8 倍 |
| 名称降序：复制结果＋排序 | 37.97 ms | 1.87 ms | 20.3 倍 |

226 万条结果下，名称排序少分配约 **43.11 MiB** 的排名和排序键数组；此数未包含原归并过程的额外缓冲。以上是排序阶段的本机测量，不代表整次搜索或其他机器都有相同提速。

复现命令：`FlashFind.exe -optimizationtest -bench`。

## 验证与兼容

- 新增 `optimizationtest`，覆盖元数据单独变化、无效及部分查询、重复事件、同批删除、旧快照不变性、目录过滤、大小写通配符，以及搜索线程切换排序后的缓存顺序。
- 原有设置、增量、通配符、排序、语法和正则自检继续作为发布门禁；新增回归也纳入 CTest。
- 数据库仍使用 v4，无需因本次升级重建；沿用现有设置与服务协议。

提供 Windows x64 安装包、便携版和 SHA-256 校验文件。
